# Fillword Generator (Филворд)

## О проекте

Fillword Generator — консольное приложение на Java 8, которое автоматически строит структуру филворда.
На вход подаются размер сетки и список русских слов. Программа укладывает все слова в квадратную сетку без пустых
клеток и выводит саму сетку и координаты клеток, по которым читается каждое слово.
При каждом запуске расположение слов получается новым (случайным).

Проект выполнен по заданию «Fillword» (задание 2).

## Правила размещения слов

1. Каждое слово размещается ровно один раз.
2. Слово читается по соседним клеткам: вверх, вниз, влево, вправо. Диагональные переходы запрещены.
3. Слово может быть прямым или «ломаным», то есть может поворачивать.
4. Внутри слова одна клетка не используется дважды.
5. Разные слова не пересекаются по клеткам.
6. Сетка заполняется полностью: пустых клеток и случайных символов нет.

Необходимое условие: суммарная длина слов равна количеству клеток сетки (`размер × размер`).

## Возможности

- Размеры сетки: 3×3, 4×4, 5×5, 6×6.
- Ввод только русских слов (регистр не важен, буква Ё поддерживается).
- Разделители слов: пробел, запятая, точка с запятой.
- Повторяющиеся слова учитываются один раз, с предупреждением.
- Ввод через консоль или через аргументы командной строки.
- Случайное расположение слов: при каждом запуске получается другой филворд.
- Воспроизводимый режим: при одинаковом зерне генератора (`new Random(42)`) получается одинаковый филворд.
- Вывод: сетка, карта номеров слов по клеткам, координаты слов (строка, столбец; нумерация с 1).
- Автоматическая проверка результата по правилам задания.
- Ограничение времени поиска (20 секунд), чтобы программа не зависала.

## Структура кода

Весь код находится в одном файле `FillwordGenerator.java` и разделён на три части.

| Часть | Исполнитель | Содержимое |
|---|---|---|
| 1. Модель данных и проверка ввода | Валента Артём | `Direction`, `Cell`, `FillwordException`, `InputParser` |
| 2. Алгоритм размещения слов | Копасов Савелий | `FillwordSolver` |
| 3. Проверка результата, вывод и запуск | Родионов Ростислав | `FillwordValidator`, `FillwordPrinter`, `FillwordGenerator` (`main`) |

### Основные классы и методы

- `Direction` — четыре допустимых направления хода со смещениями по строке и столбцу.
- `Cell` — клетка сетки (строка и столбец); `toString()` выводит координаты в виде `(строка,столбец)`.
- `FillwordException` — исключение для ошибок ввода.
- `InputParser.parseSize()` — проверяет размер сетки (3–6).
- `InputParser.parseWords()` — проверяет слова, приводит к верхнему регистру, убирает дубликаты, сверяет число букв с размером сетки.
- `FillwordSolver` — три перегруженных конструктора: с зерном `Random`, со случайным зерном, с лимитом времени по умолчанию.
- `FillwordSolver.solve()` — запускает поиск с перезапусками.
- `FillwordSolver.clear()` — очищает сетку и пути перед новой попыткой.
- `FillwordSolver.placeWord()` — выбирает стартовую клетку для очередного слова (в случайном порядке).
- `FillwordSolver.extendPath()` — рекурсивно ведёт слово по соседним свободным клеткам (направления в случайном порядке).
- `FillwordSolver.shuffled()` — возвращает случайную перестановку чисел от 0 до n−1.
- `FillwordSolver.regionsFeasible()` — отсекает безнадёжные варианты по размеру свободных областей.
- `FillwordValidator.isValid()` — независимая проверка готового результата.
- `FillwordPrinter.print()` — три перегруженных метода вывода: сетка, карта номеров слов, координаты.
- `FillwordGenerator.main()` — ввод данных, запуск поиска, вывод результата.

## Как работает алгоритм

1. Пользователь вводит размер сетки и слова.
2. Программа проверяет данные и сверяет суммарную длину слов с числом клеток.
3. Слова сортируются по убыванию длины: длинные слова сильнее всего ограничивают поиск. Слова одинаковой длины идут в случайном порядке.
4. Для каждой «хвостовой» части списка слов заранее считается множество сумм длин, которые можно получить из оставшихся слов.
5. Для очередного слова стартовые клетки перебираются в случайном порядке, и слово «проходит» по соседним свободным клеткам; направления на каждом шаге тоже выбираются в случайном порядке.
6. После размещения слова свободные клетки делятся на связные области. Размер каждой области должен быть суммой длин каких-то оставшихся слов. Если нет — вариант отбрасывается сразу.
7. Если слово не удалось разместить, алгоритм возвращается к предыдущему шагу и пробует другой вариант.
8. Если попытка тянется слишком долго (больше заданного числа шагов), поиск начинается заново с новым случайным порядком; лимит шагов при этом удваивается.
9. Когда размещены все слова, результат проверяется и выводится.

Основной алгоритм — поиск с возвратом (backtracking) с отсечением и случайными перезапусками.

### Как устроена случайность

Раньше слова перебирались всегда в одном порядке, поэтому результат повторялся. Теперь порядок перебора перемешивается,
но перебираются все варианты, поэтому решение находится всегда, когда оно существует. Перемешивание выполняет метод
`shuffled(n)`: он создаёт массив `0, 1, …, n−1` и меняет местами элементы в случайном порядке.

```java
for (int start : shuffled(size * size)) {          // стартовые клетки в случайном порядке
    ...
}
for (int index : shuffled(DIRECTIONS.length)) {    // направления в случайном порядке
    Direction d = DIRECTIONS[index];
    ...
}
```

### Зачем нужны перезапуски

При случайном порядке поиск иногда надолго застревает в неудачной ветке (на 6×6 в проверке без перезапусков три набора
из 200 не уложились в 5 секунд). Поэтому метод `solve()` ограничивает каждую попытку числом шагов:

```java
long budget = START_BUDGET;               // 3000 шагов на первую попытку
while (!timedOut) {
    clear();                              // пустая сетка
    attemptEnd = nodes + budget;          // где попытка обрывается
    cutOff = false;
    if (placeWord(0)) return true;        // решение найдено
    if (!cutOff) return false;            // перебрано всё: решения нет
    budget *= 2;                          // следующая попытка вдвое длиннее
}
```

Если попытка оборвалась по лимиту шагов (`cutOff`), сетка очищается, порядок перемешивается заново и поиск идёт снова.
Если попытка закончилась без обрыва, значит все варианты перебраны и решения нет.

## Пример

Запуск:

```text
Генератор филворда
Введите размер сетки (3, 4, 5 или 6): 5
Введите слова через пробел:
ловкость кнут бабочка ад гиря
```

Один из возможных результатов (при каждом запуске он другой):

```text
Филворд создан! (4 мс, узлов поиска: 3045, проверка правил: пройдена)

Сетка:
Б  О  Ч  Г  И  
А  Б  К  А  Р  
О  В  К  Д  Я  
Л  С  О  А  К  
Ь  Т  Т  У  Н  

Номера слов в клетках:
3  3  3  5  5  
3  3  3  3  5  
1  1  1  4  5  
1  1  1  4  2  
1  1  2  2  2  

Координаты слов (строка,столбец):
1. ЛОВКОСТЬ: (4,1) (3,1) (3,2) (3,3) (4,3) (4,2) (5,2) (5,1) 
2. КНУТ: (4,5) (5,5) (5,4) (5,3) 
3. БАБОЧКА: (2,2) (2,1) (1,1) (1,2) (1,3) (2,3) (2,4) 
4. АД: (4,4) (3,4) 
5. ГИРЯ: (1,4) (1,5) (2,5) (3,5) 
```

В этом запуске число узлов поиска (3045) больше лимита первой попытки (3000), значит первая попытка была оборвана,
и решение нашлось со второй попытки.

## Запуск

```text
javac -encoding UTF-8 FillwordGenerator.java
java FillwordGenerator
```

Или через аргументы командной строки (первый аргумент — размер, остальные — слова):

```text
java FillwordGenerator 5 ловкость кнут бабочка ад гиря
```

Для корректного отображения кириллицы в консоли Windows используйте `chcp 65001` или запуск с `-Dfile.encoding=UTF-8`.

## Сообщения об ошибках

| Ситуация | Сообщение |
|---|---|
| Размер не число | `Ошибка! Введите целое положительное число.` |
| Размер не 3–6 | `Ошибка! Можно выбрать только 3, 4, 5 или 6.` |
| Пустой список слов | `Ошибка! Список слов пуст.` |
| Не русские буквы | `Ошибка! Слова должны содержать только русские буквы.` |
| Неверное число букв | `Ошибка! Количество букв должно быть равно N (сейчас M).` |
| Время поиска вышло | `Время поиска истекло, филворд не найден.` |

## Ограничения

- Поддерживаются только сетки от 3×3 до 6×6.
- Поиск с возвратом в худшем случае экспоненциален; при превышении 20 секунд программа сообщает, что филворд не найден (это не доказывает, что решения нет).
- Время поиска случайно: на одном и том же наборе слов разные запуски могут занимать разное число шагов (для примера из задания — в среднем около 950 шагов, в худшем из 1000 запусков 17 435).
- Проверка размеров областей — необходимое, но не достаточное условие, поэтому возвраты всё равно возможны.
- Программа не проверяет, что введённые слова существуют в русском языке.
- Случайность не гарантирует «равномерности»: не все возможные расположения слов встречаются с одинаковой вероятностью.

## Тестирование

Проверялись:

- ввод: неверный размер, не число, пустой список, латиница, неверное число букв, дубликаты, разный регистр и Ё, прерванный ввод;
- пример из задания (5×5: ловкость, кнут, бабочка, ад, гиря);
- запуск через аргументы командной строки;
- по 200 случайных наборов слов для сеток 3×3, 4×4, 5×5 и 6×6 (включая слова из одной буквы): все 800 решены и прошли проверку `isValid()`, таймаутов нет, самый долгий набор — 117 мс;
- 100 запусков примера из задания дали 100 разных сеток;
- при одинаковом зерне `new Random(42)` два запуска дают одинаковую сетку.
