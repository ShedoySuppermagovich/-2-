# Разбор кода FillwordGenerator.java

Подробное объяснение каждого класса, переменной, конструктора и метода простым языком. Документ описывает текущую версию программы со встроенным словарём слов.

## 1. Что делает программа

Программа строит филворд — квадратную сетку с буквами. Пользователь задаёт только размер сетки (от 3 до 6). Слова программа берёт сама: случайным образом, без повторений, из встроенного словаря русских слов (1533 слова). Общее количество букв во всех выбранных словах равно числу клеток сетки, то есть размеру, умноженному на размер.

Каждое слово записывается в сетку цепочкой соседних клеток. Соседними считаются клетки рядом по горизонтали или вертикали, по диагонали ходить нельзя. Одна клетка принадлежит только одному слову. В конце на сетке не должно остаться пустых клеток.

Слова размещаются методом поиска с возвратом: программа ставит слово, пробует поставить следующее, а если не получилось — стирает последние буквы и пробует другой вариант. Чтобы поиск шёл быстрее, он отсекает заведомо плохие варианты, а чтобы расположение каждый раз было новым, перебор идёт в случайном порядке. Если поиск слишком долго не находит решение, он начинается заново с чистой сетки. Если же выбранный набор слов в сетку уложить нельзя, программа берёт другой набор слов из словаря.

### Из каких частей состоит файл

| Часть | За что отвечает |
|---|---|
| `Direction`, `Cell`, `FillwordException`, `InputParser`, `WordDictionary` | Данные, ввод и словарь: направления шагов, клетка сетки, ошибки, проверка введённого размера, словарь слов и случайный выбор слов для филворда. |
| `FillwordSolver` | Главный алгоритм: размещает выбранные слова в сетке. |
| `FillwordValidator`, `FillwordPrinter`, `FillwordGenerator` | Проверка готового результата, вывод на экран и запуск программы. |

### Подключаемые библиотеки (import)

- `Arrays` — набор готовых действий с массивами. Здесь используется, чтобы быстро заполнить массив одним значением.
- `NoSuchElementException` — ошибка, которая возникает, когда ввод внезапно закончился и читать больше нечего.
- `Random` — генератор случайных чисел. Используется и для выбора слов из словаря, и для случайного размещения слов в сетке.
- `Scanner` — читает то, что пользователь печатает в консоли.

## 2. Перечисление Direction

Перечисление (`enum`) — это особый вид класса, у которого есть заранее известный, неизменный набор значений. Здесь значений четыре: `UP` (вверх), `DOWN` (вниз), `LEFT` (влево) и `RIGHT` (вправо). Диагональных направлений нет, поэтому диагональный шаг в программе невозможен.

Для каждого направления хранится, насколько при шаге меняется номер строки и номер столбца.

### Переменные

| Имя | Тип | Для чего нужна |
|---|---|---|
| `dRow` | `int` | На сколько меняется номер строки при шаге в этом направлении. Может быть отрицательным (шаг к началу), нулевым (строка не меняется) или положительным (шаг к концу). |
| `dCol` | `int` | То же самое, но для номера столбца. |

Оба поля `private final`: `private` — к ним нельзя обратиться снаружи класса напрямую, `final` — после того как значение записано, изменить его нельзя.

### Конструктор

#### `Direction(int dRow, int dCol)`

Конструктор — это особый метод, который вызывается при создании значения и задаёт ему начальное состояние. У перечисления он срабатывает автоматически для каждого из четырёх значений, когда они перечислены в первой строке (в скобках после имени стоят числа, которые передаются в конструктор).

Что он делает: берёт два принесённых числа и записывает их в поля объекта. Запись `this.dRow = dRow` читается так: «в поле этого объекта положить значение одноимённого параметра». Слово `this` нужно, чтобы отличить поле от параметра, у которых одинаковое имя.

### Методы

#### `int getDRow()`

Возвращает значение поля `dRow`. Нужен, потому что само поле закрыто, а читать его снаружи надо.

#### `int getDCol()`

Возвращает значение поля `dCol`.

## 3. Класс Cell

Описывает одну клетку сетки — хранит её положение. Объекты этого класса используются для записи пути слова: путь — это цепочка клеток.

### Переменные

| Имя | Тип | Для чего нужна |
|---|---|---|
| `row` | `int` | Номер строки клетки. Нумерация внутри программы идёт с нуля. |
| `col` | `int` | Номер столбца клетки, тоже с нуля. |

Поля `private final`: закрыты от прямого доступа и после создания клетки не меняются. Если нужна другая клетка, создаётся новый объект.

### Конструктор

#### `Cell(int row, int col)`

Принимает номер строки и номер столбца и записывает их в поля. Других действий не выполняет.

### Методы

#### `int getRow()`

Возвращает номер строки.

#### `int getCol()`

Возвращает номер столбца.

#### `String toString()`

Превращает клетку в текст вида «(строка,столбец)». Перед выводом к обоим числам прибавляется единица: внутри программы счёт идёт с нуля, а людям привычнее нумерация с единицы. Пометка `@Override` говорит, что метод заменяет стандартный метод `toString`, который есть у любого объекта в Java. Благодаря этому, когда клетку добавляют к тексту, она автоматически выводится в нужном виде.

## 4. Класс FillwordException

Собственный тип ошибки. Он нужен, чтобы отличать ошибки пользователя (неверный размер, неверные слова) от прочих сбоев. Слова `extends Exception` означают, что класс создан на основе стандартного класса ошибок и получает все его возможности. Такую ошибку нужно обязательно либо обработать, либо явно объявить в методе через `throws`.

### Конструктор

#### `FillwordException(String message)`

Принимает текст сообщения об ошибке и передаёт его родительскому классу командой `super(message)`. Слово `super` означает «родитель». После этого текст можно получить методом `getMessage()`, и именно так главная часть программы показывает пользователю причину ошибки.

## 5. Класс InputParser

Проверяет то, что ввёл пользователь. Раньше класс проверял и размер сетки, и список слов. Теперь слова пользователь не вводит, их выбирает программа из словаря, поэтому проверять слова не нужно. В классе остался один метод — проверка размера. Он `static`: его можно вызывать прямо по имени класса, не создавая объект, потому что классу нечего хранить между вызовами.

### Метод

#### `static int parseSize(String text)`

Превращает введённый текст в размер сетки и проверяет его. Если что-то не так, выбрасывает `FillwordException`.

Переменные внутри метода:

- `s` — введённый текст без пробелов по краям (это делает `trim`).
- `size` — итоговое число.

Шаги:

1. Убрать пробелы по краям.
2. Проверить, что в тексте только цифры (`matches("[0-9]+")`). Если нет, например есть буквы или минус, — ошибка о том, что нужно целое положительное число. Пустая строка тоже не проходит эту проверку.
3. Если цифр больше двух, в `size` записывается 0, а число не разбирается вообще. Это защита: очень длинная запись цифр не поместилась бы в тип `int` и вызвала бы сбой при преобразовании. Ноль потом всё равно отклоняется следующей проверкой.
4. Если цифр одна или две, текст переводится в число командой `Integer.parseInt`.
5. Проверить, что число не меньше 3 и не больше 6. Иначе — ошибка о допустимых размерах.
6. Вернуть размер.

### Что убрано из класса

Из-за появления словаря из `InputParser` удалены три элемента, которые нужны были только для ввода слов вручную:

- константа `WORD_PATTERN` — шаблон «только русские буквы»;
- метод `parseWords` — разбор строки со словами, перевод в верхний регистр, отсев повторов и проверка суммы букв;
- вспомогательный метод `contains` — поиск повторяющегося слова.

Всё, что делали эти элементы, теперь обеспечивает сам словарь: слова в нём уже состоят только из русских букв и не повторяются, а сумму букв подгоняет метод `WordDictionary.pick`.

## 6. Класс WordDictionary

Хранит словарь слов и умеет случайно выбирать из него слова для филворда. Класс находится в первой части кода, рядом с остальными данными. Объекты этого класса не создаются: и словарь, и методы объявлены как `static`, то есть принадлежат самому классу.

### Откуда взят словарь

Словарь составлен из прикреплённого файла со списком слов. В исходном файле было 1598 слов, из них 65 повторяющихся. Повторы убраны, поэтому в программе 1533 уникальных слова. Это важно: если бы в словаре повторы остались, одно и то же слово могло бы попасть в филворд дважды под видом разных записей.

Слова записаны прямо в программе, в массиве `WORDS`, строчными русскими буквами (буква ё сохранена). Отдельный файл при запуске программе не нужен: достаточно одного файла с кодом. Слова собраны в массив по восемь на строку, чтобы код оставался читаемым. Полный список слов по алфавиту приведён в отдельном файле «Словарь_слов_Fillword.pdf».

Сколько в словаре слов каждой длины:

| Длина слова (букв) | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 и 12 |
|---|---|---|---|---|---|---|---|---|---|
| Слов | 10 | 194 | 478 | 740 | 53 | 33 | 17 | 6 | 2 |

Из таблицы видно, что слов из четырёх и пяти букв около 80% всего словаря. Поэтому в наборах для филворда чаще всего встречаются именно такие слова. Слов из одной буквы в словаре нет — это важно для работы метода `pick`, о чём сказано ниже.

### Переменные

| Имя | Тип | Для чего нужна |
|---|---|---|
| `MAX_ATTEMPTS` | `int` | Сколько раз метод `pick` может заново пытаться собрать набор слов, прежде чем сдаться. Значение — 1000. Константа объявлена как `private static final`: принадлежит классу, закрыта от других классов и не меняется. |
| `WORDS` | `String[]` | Сам словарь: массив из 1533 слов в нижнем регистре. Закрыт (`private`), обратиться к нему можно только через методы класса. |

### Методы

#### `static int size()`

Возвращает число слов в словаре. Нужен, потому что сам массив закрыт, а узнать его размер снаружи иногда требуется.

#### `static String[] pick(int size, Random random) throws FillwordException`

Главный метод класса. Случайно выбирает из словаря слова без повторений так, чтобы сумма их длин была равна числу клеток сетки. Параметры: `size` — сторона сетки, `random` — источник случайных чисел (передаётся снаружи, чтобы один и тот же генератор использовался во всей программе). Возвращает массив выбранных слов в верхнем регистре.

Переменные:

| Имя | Тип | Для чего нужна |
|---|---|---|
| `target` | `int` | Сколько букв нужно набрать: `size * size`, то есть число клеток сетки. |
| `attempt` | `int` | Номер текущей попытки собрать набор. Нужен, чтобы ограничить число попыток значением `MAX_ATTEMPTS`. |
| `chosen` | `String[]` | Массив для выбранных слов. Его длина равна `target` с запасом: слов не может быть больше, чем клеток, ведь самое короткое слово занимает минимум две клетки. |
| `count` | `int` | Сколько слов уже выбрано. Заодно это номер следующей свободной ячейки в `chosen`. |
| `total` | `int` | Сколько букв набрано всеми выбранными словами. |
| `index` | `int` | Номер слова в словаре, которое рассматривается сейчас. Номера берутся из случайно перемешанного списка. |
| `length` | `int` | Длина рассматриваемого слова. |
| `result` | `String[]` | Итоговый массив точной длины, без пустых ячеек в конце. |

Шаги:

1. Вычислить `target` — сколько всего клеток в сетке.
2. Запустить цикл попыток. Каждая попытка начинается с чистого набора: пустой массив `chosen`, а `count` и `total` равны нулю.
3. Перемешать номера всех слов словаря в случайном порядке (метод `shuffled`) и пройти по ним по очереди.
4. Для каждого слова узнать его длину. Если после добавления слова сумма букв превысит `target`, слово не подходит. Команда `continue` пропускает его, и берётся следующее.
5. Если слово подходит, оно переводится в верхний регистр (`toUpperCase`), записывается в `chosen`, `count` и `total` увеличиваются.
6. Как только `total` стал равен `target`, слов хватает ровно на всю сетку, и команда `break` прекращает просмотр.
7. После просмотра проверяется, получилась ли нужная сумма. Если да, создаётся массив `result` точной длины, в него командой `System.arraycopy` копируются выбранные слова, и метод возвращает его.
8. Если нужной суммы набрать не удалось, попытка считается неудачной, и цикл начинает новую — с новым перемешиванием.
9. Если за `MAX_ATTEMPTS` попыток набор так и не собрался, выбрасывается `FillwordException` с сообщением о том, что слова подобрать не удалось. На практике такого почти не бывает.

Почему слова в наборе не повторяются. Метод перебирает не слова, а их номера в перемешанном массиве, а в перемешанном массиве каждый номер стоит ровно один раз. Значит, одно и то же слово словаря не может быть выбрано дважды. Повторов нет и в самом словаре, потому что они были убраны заранее.

Почему иногда нужна новая попытка. Слова берутся «жадно»: подходящее слово сразу попадает в набор. Бывает, что до нужной суммы не хватает ровно одной буквы. Слов из одной буквы в словаре нет, поэтому добрать такой остаток невозможно. Тогда набор отбрасывается и собирается заново. Это быстро и случается нечасто, так как большинство слов короткие.

Почему слова переводятся в верхний регистр. В словаре слова записаны строчными буквами, а решатель и вывод работают с заглавными, как и раньше.

#### `private static int[] shuffled(int n, Random random)`

Возвращает массив чисел 0, 1, …, n−1 в случайном порядке. Работает так же, как одноимённый метод решателя: сначала массив заполняется числами по порядку, потом цикл идёт с конца к началу и меняет каждый элемент местами с элементом в случайной позиции от начала до текущей (перемешивание Фишера — Йетса). Подробный разбор приведён в описании метода `shuffled` класса `FillwordSolver`.

Отличие от метода решателя одно: здесь метод статический, а у статического метода нет доступа к полю `random` объекта, поэтому генератор случайных чисел передаётся в метод вторым параметром. Метод закрыт (`private`): им пользуется только `pick`.

## 7. Класс FillwordSolver

Главный класс программы. Он хранит сетку и состояние поиска и умеет размещать слова. В отличие от `InputParser`, здесь методы не статические: каждый объект-решатель имеет собственную сетку и собственные счётчики.

### Константы

Константы объявлены как `private static final`: общие для всего класса и неизменные.

| Имя | Тип | Для чего нужна |
|---|---|---|
| `EMPTY` | `char` | Символ-метка пустой клетки. Это «нулевой символ» `'\0'`, он же значение по умолчанию в массиве символов. Если в клетке он, значит, клетка свободна. |
| `DEFAULT_TIME_LIMIT_MS` | `long` | Время поиска по умолчанию в миллисекундах: 20000, то есть 20 секунд. |
| `CHECK_EVERY` | `long` | Как часто сверяться с часами: один раз на 4096 шагов. Спрашивать время на каждом шаге было бы слишком медленно. |
| `START_BUDGET` | `long` | Лимит шагов для первой попытки поиска: 3000. Если за это число шагов решение не найдено, попытка прерывается и начинается новая. |
| `DIRECTIONS` | `Direction[]` | Массив всех четырёх направлений, полученный вызовом `Direction.values()`. По нему программа перебирает возможные шаги. |

### Поля, которые задаются один раз

Эти поля объявлены `private final`: значение записывается в конструкторе и больше не меняется. Но содержимое массивов менять можно — это относится к `grid` и `paths`.

| Имя | Тип | Для чего нужна |
|---|---|---|
| `size` | `int` | Сторона сетки. |
| `words` | `String[]` | Слова, которые нужно разместить, в верхнем регистре. Это набор, выбранный из словаря методом `WordDictionary.pick`. |
| `order` | `int[]` | Порядок размещения слов. В нём хранятся не сами слова, а их номера в массиве `words`. Длинные слова идут раньше коротких, так как длинные сильнее всего ограничивают поиск. |
| `reachable` | `boolean[][]` | Таблица допустимых сумм (подробности — в методе `buildReachable`). Нужна для быстрой проверки, можно ли заполнить свободную область оставшимися словами. |
| `timeLimitMs` | `long` | Сколько миллисекунд можно искать решение. |
| `random` | `Random` | Источник случайных чисел. Если дать два решателя с одинаковым начальным числом (зерном), они построят одинаковые филворды. В программе один и тот же `Random` используется и для выбора слов из словаря, и для их размещения, поэтому с одним зерном повторяется весь результат целиком, включая набор слов. |
| `grid` | `char[][]` | Сама сетка букв — двумерный массив. Пустая клетка содержит `EMPTY`. |
| `paths` | `Cell[][]` | Пути слов. Строка с номером i содержит клетки, по которым записано слово номер i из `words`. Строки могут иметь разную длину, потому что слова разной длины (такой массив называют нерегулярным). Пока слово не размещено, его строка равна `null`, то есть «ничего». |

### Поля, которые меняются во время поиска

| Имя | Тип | Для чего нужна |
|---|---|---|
| `deadline` | `long` | Момент времени, после которого поиск надо остановить. Считается как текущее время плюс `timeLimitMs`. |
| `nodes` | `long` | Счётчик шагов поиска. Один шаг — одна попытка поставить очередную букву. Растёт всё время и не сбрасывается между попытками. |
| `attemptEnd` | `long` | Значение счётчика `nodes`, при достижении которого текущая попытка обрывается. Вычисляется как значение `nodes` в начале попытки плюс лимит шагов для неё. |
| `cutOff` | `boolean` | Признак «текущая попытка оборвана из-за лимита шагов». `true` — оборвана. |
| `timedOut` | `boolean` | Признак «общее время вышло». `true` — время истекло, поиск прекращается совсем. |

Разница между двумя признаками важна. `cutOff` означает «эта попытка была слишком долгой, можно начать заново». `timedOut` означает «пора сдаваться совсем».

### Конструкторы

У класса три конструктора. Они отличаются количеством параметров и вызывают друг друга цепочкой, поэтому одни и те же действия не дублируются. Такое объявление нескольких конструкторов называется перегрузкой.

#### `FillwordSolver(int size, String[] words, long timeLimitMs, Random random)`

Главный конструктор, в котором выполняется вся настоящая работа. Параметры: сторона сетки, слова в верхнем регистре, предел времени в миллисекундах и источник случайных чисел.

Что происходит по порядку:

1. В поля записываются `size`, `words`, `timeLimitMs` и `random`.
2. Создаётся пустая сетка `grid` размером `size` на `size`. Все клетки изначально содержат нулевой символ, то есть свободны.
3. Создаётся массив путей `paths` — по одной строке на каждое слово. Сами строки пока не созданы, в них `null`.
4. Вызывается `orderByLength`, и результат записывается в `order`.
5. Вызывается `buildReachable`, и результат записывается в `reachable`.

Порядок действий важен. Поле `random` должно быть записано до вызова `orderByLength`, потому что этот метод использует случайные числа. А `order` должен быть готов до `buildReachable`, потому что таблица строится по порядку слов.

#### `FillwordSolver(int size, String[] words, long timeLimitMs)`

Упрощённый конструктор без параметра `random`. Командой `this(...)` он вызывает главный конструктор и сам подставляет `new Random()` — генератор со случайным зерном. Из-за этого расположение слов получается разным при каждом запуске. В текущей версии программы этот конструктор напрямую не вызывается: главная часть использует конструктор с четырьмя параметрами, чтобы передать общий `Random`.

#### `FillwordSolver(int size, String[] words)`

Самый простой конструктор: без времени и без `random`. Он вызывает предыдущий конструктор, подставляя время по умолчанию `DEFAULT_TIME_LIMIT_MS` (20 секунд). В текущей версии программы он тоже напрямую не вызывается и оставлен для удобства: им можно воспользоваться, если слова уже известны и нужен готовый решатель с настройками по умолчанию.

### Методы

#### `private int[] orderByLength(String[] words)`

Определяет порядок размещения слов и возвращает массив их номеров. Сначала номера перемешиваются в случайном порядке вызовом `shuffled`, затем сортируются по убыванию длины слова.

Используется сортировка вставками: массив просматривается слева направо, и каждый очередной элемент вставляется на своё место среди уже отсортированных. Переменные цикла:

- `order` — массив номеров слов (сначала случайная перестановка, потом отсортированный).
- `i` — позиция элемента, который сейчас вставляется. Цикл начинается с единицы, потому что первый элемент один и уже «отсортирован».
- `current` — номер слова, которое сейчас вставляется.
- `j` — позиция слева от места вставки; сначала указывает на соседа слева, потом уходит влево.

Пока слева стоит слово строго короче вставляемого, оно сдвигается на одну позицию вправо. Когда подходящее место найдено, `current` ставится на него. Поскольку сравнение строгое (знак «меньше», а не «меньше или равно»), слова одинаковой длины не меняются местами. Поэтому их случайный порядок, полученный в начале, сохраняется. Итог: слова разной длины идут от длинных к коротким, а равные по длине — в случайном порядке.

#### `private boolean[][] buildReachable()`

Строит таблицу `reachable`. Это таблица «да/нет»: значение `reachable[k][s]` равно `true`, если из слов, начиная с k-го по порядку размещения и до конца, можно выбрать несколько так, чтобы их общая длина была ровно `s`. Другими словами, можно ли набрать ровно `s` клеток из ещё не размещённых слов.

Переменные:

- `cells` — общее число клеток сетки.
- `result` — таблица. В ней на одну строку больше, чем слов (последняя строка означает «слов не осталось»), и на один столбец больше, чем клеток (столбец для суммы ноль).
- `k` — номер слова в порядке размещения; цикл идёт с последнего к первому.
- `len` — длина k-го слова.
- `s` — проверяемая сумма.

Как заполняется: когда слов не осталось, можно набрать только сумму ноль, поэтому в последней строке истинно только значение для нуля. Дальше для каждого слова, двигаясь с конца, сумма `s` считается достижимой в двух случаях. Либо её можно набрать и без этого слова (значение в строке ниже уже истинно). Либо слово можно взять: тогда `s` не меньше длины слова, а оставшаяся сумма `s - len` достижима без него. Таблица считается один раз заранее, а потом только читается.

#### `boolean solve()`

Запускает весь поиск. Возвращает `true`, если филворд построен, и `false`, если не построен (либо решения нет, либо вышло время). Метод работает с перезапусками: если одна попытка идёт слишком долго, он начинает заново, а случайный порядок на новой попытке будет уже другой.

Переменная `budget` — лимит шагов для текущей попытки; в начале равна `START_BUDGET`.

Что происходит:

1. Вычисляется срок окончания `deadline` — текущее время плюс лимит. Счётчик `nodes` обнуляется, признак `timedOut` сбрасывается.
2. Запускается цикл, который работает, пока время не вышло.
3. В начале каждой попытки вызывается `clear()` — сетка очищается.
4. Вычисляется `attemptEnd` — номер шага, на котором эта попытка будет оборвана. Сбрасывается `cutOff`.
5. Вызывается `placeWord(0)` — размещение слов начиная с первого. Если вернулось `true`, все слова размещены, и метод возвращает `true`.
6. Если размещение не удалось и попытка не обрывалась (`cutOff` равен `false`), значит, все варианты перебраны и решения не существует. Метод возвращает `false`.
7. Если попытка была оборвана, `budget` удваивается и начинается следующая попытка. Каждая новая попытка получает вдвое больше шагов, чем предыдущая.
8. Если цикл закончился из-за времени, метод возвращает `false`.

#### `private void clear()`

Готовит сетку к новой попытке. В каждую строку сетки записывается `EMPTY` (метод `Arrays.fill` заполняет всю строку одним значением), а все пути слов сбрасываются в `null`.

#### `private boolean placeWord(int k)`

Размещает слово, которое стоит на позиции `k` в порядке размещения. Это рекурсивный метод: он вызывает сам себя (через `extendPath`) для следующего слова. Возвращает `true`, если удалось разместить это слово и все оставшиеся.

Переменные:

- `k` — номер текущего слова в порядке размещения.
- `wordIndex` — номер этого слова в массиве `words` (берётся из `order`).
- `word` — само слово.
- `start` — номер стартовой клетки. Клетки сетки пронумерованы по порядку, строка за строкой.
- `r`, `c` — строка и столбец стартовой клетки. Получаются делением номера на `size` (целая часть — строка) и взятием остатка (столбец).
- `path` — массив клеток для пути этого слова, по одной на каждую букву.

Шаги:

1. Если `k` равен числу слов, то все слова уже размещены — возвращается `true`. Это условие остановки рекурсии.
2. Вызывается `regionsFeasible(k)`. Если свободные области уже не подходят под оставшиеся слова, дальше идти бессмысленно, возвращается `false`.
3. Перебираются все клетки сетки в случайном порядке (`shuffled`). Занятые пропускаются.
4. Для свободной клетки создаётся `path`, в его начало записывается эта клетка, путь записывается в `paths`, а в сетку ставится первая буква слова.
5. Вызывается `extendPath`, чтобы дописать остальные буквы. Если получилось — возвращается `true`.
6. Если не получилось, первая буква стирается, и пробуется следующая клетка. Это и есть «возврат»: отмена неудачного выбора.
7. Если время вышло или попытка оборвана, метод сразу сбрасывает путь и выходит с `false`, не перебирая остальные клетки.
8. Если все клетки перебраны и ничего не вышло, путь сбрасывается и возвращается `false`. Тогда предыдущее слово будет пробовать другой путь.

#### `private boolean extendPath(int k, String word, int pos, Cell[] path)`

Дописывает слову очередную букву в соседнюю клетку и так, рекурсивно, ставит все буквы. Параметры: `k` — номер слова в порядке размещения, `word` — само слово, `pos` — номер буквы, которую нужно поставить сейчас, `path` — путь, который строится.

Переменные: `last` — клетка, в которой стоит предыдущая буква; `index` — номер направления; `d` — выбранное направление; `nr`, `nc` — строка и столбец соседней клетки (к строке и столбцу `last` прибавляются смещения направления).

Шаги:

1. Счётчик `nodes` увеличивается на единицу. Каждые 4096 шагов проверяется время: если оно превышено, `timedOut` становится `true`.
2. Если счётчик превысил `attemptEnd`, `cutOff` становится `true` — попытка слишком затянулась.
3. Если выставлен любой из этих признаков, метод возвращает `false`, и вся цепочка вызовов быстро сворачивается.
4. Если `pos` равен длине слова, то все буквы уже стоят. Тогда вызывается `placeWord(k + 1)` — переход к следующему слову.
5. Иначе берётся клетка последней поставленной буквы и в случайном порядке перебираются четыре направления.
6. Если соседняя клетка в этом направлении занята или за пределами сетки, она пропускается.
7. Если свободна, в неё ставится буква, клетка записывается в путь, и метод вызывает сам себя для следующей буквы. Если дальше получилось — возвращается `true`.
8. Если нет, клетка освобождается (откат), и пробуется следующее направление.
9. Если все направления перепробованы, возвращается `false`.

#### `private boolean regionsFeasible(int k)`

Отсекает заведомо безнадёжные варианты. Свободные клетки сетки могут распасться на несколько отдельных «областей» — групп клеток, связанных между собой соседством. Слово нельзя поставить в две разные области сразу, поэтому каждая область должна заполняться целиком, и её размер должен складываться из длин каких-то оставшихся слов. Метод проверяет это условие для каждой области. Если хотя бы одна область не подходит, возвращается `false`.

Переменные:

- `seen` — таблица «да/нет»: уже ли клетка учтена в какой-либо области.
- `stack` — стек (стопка), в которую складываются клетки, ожидающие просмотра. Клетка хранится одним числом: строка, умноженная на `size`, плюс столбец.
- `r`, `c` — координаты клетки, с которой начинается поиск новой области.
- `top` — сколько элементов сейчас лежит в стеке (указывает на первое свободное место).
- `count` — размер текущей области.
- `cur` — клетка, которую достали из стека; `nr`, `nc` — её соседи.

Как работает: метод проходит по всем клеткам. Занятые и уже учтённые пропускаются. Свободная неучтённая клетка — это начало новой области. Её кладут в стек и отмечают в `seen`. Пока стек не пуст, из него достаётся клетка, счётчик `count` увеличивается, а все свободные неучтённые соседи отмечаются и кладутся в стек. Это называется поиском в глубину. Когда стек опустел, область обойдена, и в `count` лежит её размер. Затем смотрим в таблицу `reachable[k][count]`: если там `false`, такого размера не набрать, и возвращается `false`. Если все области прошли проверку, возвращается `true`.

Это условие необходимое, но не достаточное: проверка может пропустить вариант, который на самом деле тупиковый. Но плохие варианты она отсекает очень рано.

#### `private int[] shuffled(int n)`

Возвращает массив чисел 0, 1, 2, …, n−1, перемешанных в случайном порядке. Используется везде, где нужно перебирать что-то в случайном порядке: клетки, направления, слова одинаковой длины.

Переменные: `result` — массив; `i` — текущая позиция; `j` — случайная позиция; `tmp` — временное хранилище для обмена.

Как работает: сначала массив заполняется числами по порядку. Затем цикл идёт от конца массива к началу. Для каждой позиции `i` выбирается случайное число `j` от 0 до `i` включительно (`random.nextInt(i + 1)`), и элементы на позициях `i` и `j` меняются местами. Для обмена нужна временная переменная `tmp`: без неё одно из значений было бы потеряно. Этот способ называется перемешиванием Фишера — Йетса; он даёт равную вероятность любой перестановке.

#### `private boolean isFree(int r, int c)`

Проверяет, можно ли занять клетку с номером строки `r` и столбца `c`. Возвращает `true`, только когда выполняются все условия сразу: строка и столбец не выходят за границы сетки, и в клетке лежит `EMPTY`. Проверка границ идёт первой не случайно: если бы мы сначала обратились к клетке за пределами сетки, программа вылетела бы с ошибкой. Но Java проверяет условия слева направо и останавливается на первом ложном, поэтому до обращения к массиву дело не доходит.

#### `char[][] getGrid()`

Возвращает сетку букв.

#### `Cell[][] getPaths()`

Возвращает пути всех слов.

#### `long getNodes()`

Возвращает общее число шагов поиска за все попытки.

#### `boolean isTimedOut()`

Возвращает `true`, если поиск остановлен из-за истечения времени.

Эти четыре метода нужны, потому что сами поля закрыты (`private`). Через них остальные классы получают результат работы решателя.

## 8. Класс FillwordValidator

Независимая проверка готового результата. Она не доверяет решателю и проверяет итог заново, по самим правилам филворда. Метод статический.

#### `static boolean isValid(char[][] grid, String[] words, Cell[][] paths)`

Параметры: сетка букв, слова и пути слов. Возвращает `true`, если всё правильно, и `false` при любом нарушении.

Переменные:

- `size` — сторона сетки.
- `used` — таблица «да/нет»: занята ли клетка каким-нибудь словом.
- `i` — номер слова; `path` — его путь.
- `j` — номер буквы в слове.
- `r`, `c` — строка и столбец клетки, в которой стоит эта буква.

Что проверяется для каждого слова и каждой его буквы:

- Путь существует и его длина равна длине слова; в пути нет пустых мест.
- Клетка ещё не использована другим словом или этим же словом ранее.
- Буква в сетке в этой клетке совпадает с соответствующей буквой слова.
- Каждая клетка пути, кроме первой, является соседней по стороне с предыдущей. Это проверяется так: сумма модулей разницы строк и разницы столбцов должна быть равна единице. Для соседей по стороне она равна единице, для диагональных клеток двум, для далёких — больше.

В конце проверяется, что в таблице `used` нет ни одной незанятой клетки: сетка должна быть заполнена полностью.

## 9. Класс FillwordPrinter

Выводит результат на экран. В классе три метода с одним и тем же именем `print`, но с разными параметрами. Такое называется перегрузкой методов: Java по набору переданных параметров сама понимает, какой из трёх нужен.

#### `static void print(char[][] grid)`

Печатает сетку букв. Сначала выводит заголовок. Затем для каждой строки сетки собирает текст в `StringBuilder` (удобный инструмент для постепенной сборки строки), дописывая каждую букву и пробел после неё, и печатает готовую строку. Переменные: `row` — строка сетки, `sb` — собираемый текст, `ch` — текущая буква.

#### `static void print(Cell[][] paths, int size)`

Печатает карту принадлежности: в каждой клетке стоит номер слова, которому она принадлежит.

Переменные: `owner` — числовая таблица размером с сетку, `i` — номер слова, `cell` — клетка пути, `row` — строка таблицы, `value` — число в клетке, `sb` — собираемый текст.

Как работает: для каждого слова по каждой клетке его пути в таблицу `owner` записывается номер слова плюс один (нумерация для человека идёт с единицы). Потом таблица печатается построчно. Формат `%-3d` означает: вывести целое число, выровняв по левому краю в поле шириной три символа. Благодаря этому столбцы выстраиваются ровно.

#### `static void print(String[] words, Cell[][] paths)`

Печатает координаты каждого слова. Для каждого слова собирается строка: номер с точкой, слово, двоеточие и затем все клетки его пути по порядку. Клетки печатаются через `toString` класса `Cell`, то есть в виде «(строка,столбец)» с нумерацией с единицы.

## 10. Класс FillwordGenerator

Главный класс, с которого начинается выполнение программы. Он публичный (`public`) и имеет то же имя, что и файл, как того требует Java. После появления словаря его работа изменилась: теперь он не принимает слова от пользователя, а сам запрашивает их у словаря и перебирает наборы, пока не найдёт такой, который удастся уложить в сетку.

### Константы

| Имя | Тип | Для чего нужна |
|---|---|---|
| `MAX_SETS` | `int` | Сколько наборов слов программа попробует, прежде чем сдаться. Значение — 200. Нужна потому, что случайно выбранный набор иногда уложить в сетку невозможно, и тогда берётся другой. |
| `SET_TIME_LIMIT_MS` | `long` | Сколько миллисекунд решатель может искать решение для одного набора слов. Значение — 2000, то есть 2 секунды. Если время вышло, программа не ждёт дальше, а берёт другой набор. |

### Методы

#### `public static void main(String[] args)`

Точка входа: Java начинает выполнение программы именно с этого метода. Параметр `args` — массив аргументов командной строки, то есть слов, которые пользователь написал после имени программы при запуске. Теперь в нём нужен только один аргумент — размер сетки.

Переменные:

- `scanner` — читает ввод с клавиатуры.
- `size` — размер сетки.

Что происходит:

1. Создаётся `Scanner`.
2. Внутри блока `try` (блок «попробовать») проверяется, передан ли хотя бы один аргумент. Если да, первый аргумент разбирается как размер.
3. Если аргументов нет, программа выводит приглашение и читает размер из консоли.
4. Вызывается `solveAndShow(size)` — подбор слов, решение и вывод. Слова теперь не передаются: их подбирает сама программа.
5. Блок `catch (FillwordException e)` ловит ошибки: неверный размер, а также ситуацию, когда словарь не смог составить набор слов. Печатается «Ошибка!» с текстом причины.
6. Блок `catch (NoSuchElementException e)` ловит ситуацию, когда ввод оборвался и читать больше нечего.
7. Блок `finally` выполняется всегда и закрывает `scanner`.

#### `private static void solveAndShow(int size) throws FillwordException`

Подбирает слова, запускает решатель и показывает результат. Запись `throws FillwordException` в заголовке означает, что метод сам ошибку не обрабатывает, а передаёт её вызвавшему методу: так ошибка метода `pick` доходит до блока `catch` в `main`.

Переменные:

| Имя | Тип | Для чего нужна |
|---|---|---|
| `random` | `Random` | Один генератор случайных чисел на всю работу: он используется и для выбора слов, и для размещения. Если заменить `new Random()` на `new Random(42)`, результат при каждом запуске будет одинаковым. |
| `start` | `long` | Момент начала всей работы. От него считается общее время. |
| `sets` | `int` | Номер текущего набора слов. Заодно это число наборов, которые пришлось попробовать. |
| `words` | `String[]` | Набор слов, выбранный из словаря для текущей попытки. |
| `solver` | `FillwordSolver` | Решатель для этого набора. Создаётся конструктором с четырьмя параметрами: сторона сетки, слова, лимит времени `SET_TIME_LIMIT_MS` и общий `random`. |
| `time` | `long` | Сколько миллисекунд прошло от начала работы до успеха. |

Шаги:

1. Создаются генератор `random` и запоминается время начала.
2. Запускается цикл по наборам: от первого до `MAX_SETS`-го.
3. В каждом круге вызывается `WordDictionary.pick(size, random)` — программа получает новый случайный набор слов.
4. Для этого набора создаётся решатель, и вызывается `solve()`.
5. Если решение найдено, вычисляется затраченное время, вызывается метод `show`, и работа завершается командой `return`.
6. Если решения нет (или время набора вышло), цикл переходит к следующему кругу и берёт другой набор слов.
7. Если все наборы перепробованы и ничего не вышло, печатается сообщение с просьбой запустить программу ещё раз.

На практике первый же набор слов почти всегда укладывается в сетку, поэтому перебор нескольких наборов происходит редко.

#### `private static void show(int size, String[] words, FillwordSolver solver, int sets, long time)`

Новый метод: он выделен из прежнего `solveAndShow`, чтобы не смешивать подбор слов и вывод результата. Параметры: размер сетки, набор слов, решатель с готовым результатом, число опробованных наборов и затраченное время.

Переменная `valid` хранит итог независимой проверки `FillwordValidator.isValid`.

Что происходит: проверяется результат; печатается строка об успехе с временем, числом наборов слов, числом шагов поиска и итогом проверки; затем вызываются три метода `print`: сетка, карта номеров слов и координаты слов.

### Что убрано из класса

- Метод `join` — он склеивал слова из аргументов командной строки в одну строку. Слов в аргументах больше нет, поэтому метод не нужен.
- Параметр `words` у `solveAndShow` — теперь слова подбираются внутри метода.
- Сообщение «Время поиска истекло, филворд не найден» — время теперь ограничено для каждого набора отдельно, и при его истечении просто берётся другой набор.

## 11. Как всё работает вместе

1. Программа запускается с метода `main`.
2. `InputParser` проверяет размер сетки. При ошибке выбрасывается `FillwordException`, и программа сообщает причину и завершается.
3. `solveAndShow` запускает цикл по наборам слов. В каждом круге `WordDictionary.pick` случайно выбирает из словаря слова без повторений, так чтобы число букв равнялось числу клеток.
4. Создаётся `FillwordSolver`. Он перемешивает слова одинаковой длины, упорядочивает слова от длинных к коротким и строит таблицу допустимых сумм.
5. `solve()` запускает попытки. В каждой попытке `placeWord` и `extendPath` по очереди размещают слова, стартуя из случайных клеток и двигаясь в случайных направлениях. При тупике они откатываются назад.
6. Перед каждым словом `regionsFeasible` отсекает варианты, в которых остались области неподходящего размера.
7. Если попытка длится слишком долго, она обрывается, и начинается новая с большим лимитом шагов.
8. Если для набора слов решения нет или время набора (2 секунды) вышло, `solveAndShow` берёт новый набор из словаря. Так делается не более 200 раз.
9. Когда все слова размещены, `FillwordValidator` независимо проверяет результат, а `FillwordPrinter` выводит сетку, карту и координаты.

## 12. Что изменилось в коде из-за словаря

Краткий итог всех изменений по сравнению с прежней версией, где слова вводил пользователь.

| Что | Как изменилось |
|---|---|
| Ввод | Пользователь вводит только размер сетки. Слова больше не вводятся ни с клавиатуры, ни через аргументы командной строки. |
| Новый класс `WordDictionary` | Хранит словарь из 1533 слов и выбирает из него случайные слова без повторений с нужной суммой букв. |
| `InputParser` | Остался только метод `parseSize`. Удалены `parseWords`, `contains` и шаблон `WORD_PATTERN`. |
| `FillwordSolver` | Алгоритм размещения слов не менялся. Один и тот же `Random` теперь общий для выбора слов и их размещения. |
| `solveAndShow` | Теперь принимает только размер, сам подбирает наборы слов и перебирает их (до 200), пока не найдёт подходящий. Вывод вынесен в метод `show`. |
| Лимит времени | Раньше 20 секунд на весь поиск. Теперь 2 секунды на каждый набор слов. |
| Аргументы командной строки | Нужен один аргумент — размер. Метод `join` удалён. |
| Сообщения об ошибках | Убраны ошибки про пустой список слов, нерусские буквы и неверное число букв. Добавлена ошибка о том, что не удалось подобрать слова из словаря. |
| Вывод результата | В строку об успехе добавлено число опробованных наборов слов. |
