# Fillword Generator (Филворд)

ЭТО ДЕЛАЛ НЕ ТОЛЬКО САВЕЛИЙ!!! ЕЩЁ АРТЁМ ВАЛЕНТА И РОДИОНОВ РОСТИСЛАВ


## О проекте

Fillword Generator — консольное приложение на Java 8, которое автоматически строит структуру филворда.
На вход подаётся только размер сетки. Слова программа **сама случайно выбирает из встроенного словаря** (1533 русских слова)
так, чтобы они не повторялись и в сумме давали ровно столько букв, сколько клеток в сетке. Затем программа укладывает
все слова в квадратную сетку без пустых клеток и выводит саму сетку и координаты клеток, по которым читается каждое слово.
При каждом запуске набор слов и их расположение получаются новыми (случайными).

Проект выполнен по заданию «Fillword» (задание 2).

## Правила размещения слов

1. Каждое слово размещается ровно один раз.
2. Слово читается по соседним клеткам: вверх, вниз, влево, вправо. Диагональные переходы запрещены.
3. Слово может быть прямым или «ломаным», то есть может поворачивать.
4. Внутри слова одна клетка не используется дважды.
5. Разные слова не пересекаются по клеткам.
6. Сетка заполняется полностью: пустых клеток и случайных символов нет.
7. Слова берутся из словаря и не повторяются внутри одного филворда.

Необходимое условие: суммарная длина слов равна количеству клеток сетки (`размер × размер`). Программа подбирает слова
именно так, чтобы это условие выполнялось.

## Словарь слов

Словарь взят из файла со списком слов (`words_xml.txt`, формат XML-ресурсов с массивом `words`) и встроен в код как
массив строк `WORDS` в классе `WordDictionary`. Отдельный файл при запуске программе не нужен.

- В исходном файле было 1598 слов, из них 65 повторов; в словарь вошли **1533 уникальных слова**.
- Все слова записаны строчными русскими буквами (буква ё сохранена). При выборе они переводятся в верхний регистр.
- Все слова словаря в алфавитном порядке собраны в файле `Словарь_слов_Fillword.pdf`.

Распределение слов по длине:

| Длина слова (букв) | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 | 12 |
|---|---|---|---|---|---|---|---|---|---|---|
| Слов | 10 | 194 | 478 | 740 | 53 | 33 | 17 | 6 | 1 | 1 |

Около 80% словаря составляют слова из 4 и 5 букв, поэтому чаще всего в набор попадают именно они.

Чтобы добавить свои слова, допишите их в массив `WORDS`: только русские буквы, без пробелов, не повторяя уже имеющиеся.

## Возможности

- Размеры сетки: 3×3, 4×4, 5×5, 6×6.
- Слова выбираются случайно из встроенного словаря, без повторений в одном филворде.
- Набор слов подбирается так, чтобы суммарное число букв равнялось числу клеток сетки.
- Если выбранный набор не удаётся уложить в сетку, автоматически подбирается другой набор.
- Ввод только размера сетки: через консоль или первым аргументом командной строки.
- Случайное расположение слов: при каждом запуске получается другой филворд.
- Воспроизводимый режим: при одинаковом зерне генератора (`new Random(42)`) получается одинаковый филворд.
- Вывод: сетка, карта номеров слов по клеткам, координаты слов (строка, столбец; нумерация с 1).
- Автоматическая проверка результата по правилам задания.
- Ограничение времени поиска (2 секунды на один набор слов), чтобы программа не зависала.

## Структура кода

Весь код находится в одном файле `FillwordGenerator.java` и разделён на три части.

| Часть | Исполнитель | Содержимое |
|---|---|---|
| 1. Модель данных, проверка ввода и словарь | Родионов Ростислав | `Direction`, `Cell`, `FillwordException`, `InputParser`, `WordDictionary` |
| 2. Алгоритм размещения слов | Копасов Савелий | `FillwordSolver` |
| 3. Проверка результата, вывод и запуск | Артем Валента | `FillwordValidator`, `FillwordPrinter`, `FillwordGenerator` (`main`) |

### Основные классы и методы

- `Direction` — четыре допустимых направления хода со смещениями по строке и столбцу.
- `Cell` — клетка сетки (строка и столбец); `toString()` выводит координаты в виде `(строка,столбец)`.
- `FillwordException` — исключение для ошибок ввода и подбора слов.
- `InputParser.parseSize()` — проверяет размер сетки (3–6).
- `WordDictionary.WORDS` — массив слов словаря (1533 слова).
- `WordDictionary.size()` — возвращает число слов в словаре.
- `WordDictionary.pick(size, random)` — случайно выбирает из словаря слова без повторений так, чтобы сумма их длин равнялась `size × size`; слова возвращаются в верхнем регистре.
- `WordDictionary.shuffled()` — случайная перестановка номеров слов словаря.
- `FillwordSolver` — три перегруженных конструктора: с зерном `Random`, со случайным зерном, с лимитом времени по умолчанию.
- `FillwordSolver.solve()` — запускает поиск с перезапусками.
- `FillwordSolver.clear()` — очищает сетку и пути перед новой попыткой.
- `FillwordSolver.placeWord()` — выбирает стартовую клетку для очередного слова (в случайном порядке).
- `FillwordSolver.extendPath()` — рекурсивно ведёт слово по соседним свободным клеткам (направления в случайном порядке).
- `FillwordSolver.shuffled()` — возвращает случайную перестановку чисел от 0 до n−1.
- `FillwordSolver.regionsFeasible()` — отсекает безнадёжные варианты по размеру свободных областей.
- `FillwordValidator.isValid()` — независимая проверка готового результата.
- `FillwordPrinter.print()` — три перегруженных метода вывода: сетка, карта номеров слов, координаты.
- `FillwordGenerator.main()` — ввод размера, запуск подбора слов и поиска, вывод результата.
- `FillwordGenerator.solveAndShow()` — в цикле подбирает набор слов, запускает решатель и при успехе выводит результат.

## Как работает алгоритм

1. Пользователь вводит размер сетки (или передаёт его аргументом).
2. Программа проверяет размер и вычисляет число клеток (`размер × размер`).
3. `WordDictionary.pick()` перемешивает словарь и проходит по нему по порядку: слово берётся, если после него суммарная длина не превысит число клеток. Так продолжается, пока сумма не станет ровно равной числу клеток. Каждое слово словаря встречается в наборе не более одного раза. Если сумму набрать не удалось (например, не хватило одной буквы), набор отбрасывается и подбирается заново.
4. Слова набора сортируются по убыванию длины: длинные слова сильнее всего ограничивают поиск. Слова одинаковой длины идут в случайном порядке.
5. Для каждой «хвостовой» части списка слов заранее считается множество сумм длин, которые можно получить из оставшихся слов.
6. Для очередного слова стартовые клетки перебираются в случайном порядке, и слово «проходит» по соседним свободным клеткам; направления на каждом шаге тоже выбираются в случайном порядке.
7. После размещения слова свободные клетки делятся на связные области. Размер каждой области должен быть суммой длин каких-то оставшихся слов. Если нет — вариант отбрасывается сразу.
8. Если слово не удалось разместить, алгоритм возвращается к предыдущему шагу и пробует другой вариант.
9. Если попытка тянется слишком долго (больше заданного числа шагов), поиск начинается заново с новым случайным порядком; лимит шагов при этом удваивается.
10. Если для выбранного набора слов решения нет или вышло время (2 секунды), `solveAndShow()` подбирает новый набор слов и повторяет поиск. Всего пробуется не более 200 наборов.
11. Когда размещены все слова, результат проверяется и выводится.

Основной алгоритм — поиск с возвратом (backtracking) с отсечением и случайными перезапусками.

### Как устроен выбор слов

Выбор слов выполняет метод `pick`. Он не подгоняет набор под ответ, а просто идёт по случайно перемешанному словарю:

```java
for (int index : shuffled(WORDS.length, random)) {
    int length = WORDS[index].length();
    if (total + length > target) {
        continue;                              // слово не помещается по числу букв
    }
    chosen[count++] = WORDS[index].toUpperCase();
    total += length;
    if (total == target) {
        break;                                 // набрано ровно столько букв, сколько клеток
    }
}
```

Так как каждый номер слова встречается в перемешанном массиве один раз, повторов в наборе быть не может.
Для словаря нет слов из одной буквы, поэтому набор не получится, если до конца не хватает ровно одной буквы.
В этом случае метод пробует снова с новым перемешиванием (до 1000 раз).

### Как устроена случайность

Случайность теперь есть на трёх уровнях: какие слова попадут в набор, в каком порядке они будут размещены и в какие клетки
попадёт каждое слово. Порядок перебора перемешивается, но перебираются все варианты, поэтому решение для выбранного набора
находится всегда, когда оно существует. Перемешивание выполняет метод `shuffled(n)`: он создаёт массив `0, 1, …, n−1`
и меняет местами элементы в случайном порядке (алгоритм Фишера — Йетса).

```java
for (int start : shuffled(size * size)) {          // стартовые клетки в случайном порядке
    ...
}
for (int index : shuffled(DIRECTIONS.length)) {    // направления в случайном порядке
    Direction d = DIRECTIONS[index];
    ...
}
```

### Зачем нужны перезапуски

При случайном порядке поиск иногда надолго застревает в неудачной ветке (на 6×6 в проверке без перезапусков три набора
из 200 не уложились в 5 секунд). Поэтому метод `solve()` ограничивает каждую попытку числом шагов:

```java
long budget = START_BUDGET;               // 3000 шагов на первую попытку
while (!timedOut) {
    clear();                              // пустая сетка
    attemptEnd = nodes + budget;          // где попытка обрывается
    cutOff = false;
    if (placeWord(0)) return true;        // решение найдено
    if (!cutOff) return false;            // перебрано всё: решения нет
    budget *= 2;                          // следующая попытка вдвое длиннее
}
```

Если попытка оборвалась по лимиту шагов (`cutOff`), сетка очищается, порядок перемешивается заново и поиск идёт снова.
Если попытка закончилась без обрыва, значит все варианты перебраны и для этого набора слов решения нет; тогда
`solveAndShow()` выбирает другой набор слов.

### Перебор наборов слов

```java
for (int sets = 1; sets <= MAX_SETS; sets++) {                  // MAX_SETS = 200
    String[] words = WordDictionary.pick(size, random);
    FillwordSolver solver = new FillwordSolver(size, words, SET_TIME_LIMIT_MS, random);   // 2000 мс
    if (solver.solve()) {
        show(size, words, solver, sets, time);
        return;
    }
}
```

На практике (см. раздел «Тестирование») первый же набор слов раскладывается почти всегда.

### Воспроизводимый результат

Чтобы при каждом запуске получался один и тот же набор слов и один и тот же филворд, в методе `solveAndShow()` замените
`new Random()` на `new Random(42)`. Зерно используется и для выбора слов, и для размещения, поэтому результат повторяется полностью.

## Сообщения об ошибках

| Ситуация | Сообщение |
|---|---|
| Размер не число (или пустой ввод) | `Ошибка! Введите целое положительное число.` |
| Размер не 3–6 | `Ошибка! Можно выбрать только 3, 4, 5 или 6.` |
| Ввод прерван | `Ошибка! Ввод прерван.` |
| Не удалось набрать слова нужной длины | `Ошибка! Не удалось подобрать слова из словаря.` |
| Ни один из 200 наборов не уложился в сетку | `Не удалось построить филворд, запустите программу ещё раз.` |

Сообщения об ошибках слов (пустой список, не русские буквы, неверное число букв) убраны: слова теперь вводит не пользователь, а берёт программа из проверенного словаря.

## Ограничения

- Поддерживаются только сетки от 3×3 до 6×6.
- Слова нельзя ввести вручную: используется только встроенный словарь (свои слова можно добавить в массив `WORDS`).
- Поиск с возвратом в худшем случае экспоненциален; для одного набора слов он ограничен 2 секундами, после чего берётся другой набор. Если не уложился ни один из 200 наборов, программа просит запустить её заново (это не доказывает, что решения не существует).
- Время поиска случайно: на разных наборах слов число шагов разное.
- Проверка размеров областей — необходимое, но не достаточное условие, поэтому возвраты всё равно возможны.
- Программа не проверяет смысл и допустимость слов в словаре: что в файле, то и попадёт в филворд. Словарь содержит и такие слова, как «ад» или «батл», на которые стоит обратить внимание перед публичным использованием.
- Случайность не гарантирует «равномерности»: не все возможные наборы и расположения слов встречаются с одинаковой вероятностью. В частности, слова из 4 и 5 букв составляют около 80% словаря, поэтому в наборах преобладают они.
- Алгоритм не следит за тем, чтобы в сетке случайно не образовались другие читаемые слова.

## Тестирование

Проверялось:

- ввод: неверный размер (7), не число (abc), пустой ввод, прерванный ввод;
- запуск через консоль и через аргумент командной строки;
- по 500 запусков для каждого размера 3×3, 4×4, 5×5 и 6×6 (всего 2000): во всех запусках филворд построен и прошёл проверку `isValid()`, все слова набора взяты из словаря, повторов слов внутри набора нет, суммарное число букв равно числу клеток, таймаутов и неудач нет;
- во всех 2000 запусках первый же набор слов удалось уложить в сетку;
- самый долгий запуск: 9 мс (3×3), 4 мс (4×4), 11 мс (5×5), 49 мс (6×6); средняя длительность — от 0,1 до 0,6 мс;
- в каждой серии из 500 запусков все результаты получились разными;
- при одинаковом зерне `Random(42)` два запуска дают одинаковые слова и сетку, а при другом зерне результат отличается;
- сам алгоритм размещения (он не менялся) ранее проверен на 200 случайных наборах слов для каждого размера (включая слова из одной буквы): все 800 решены и прошли проверку, самый долгий набор — 117 мс.

Код компилировался с ключами `-source 8 -target 8`. Перед сдачей рекомендуется один раз собрать проект на вашей Java 8.

## Что изменилось в версии со словарём

- Добавлен класс `WordDictionary` со словарём из 1533 слов и методом случайного выбора слов без повторений.
- Слова теперь не вводятся пользователем: достаточно указать размер сетки.
- Удалены `InputParser.parseWords()`, вспомогательный метод `contains()` и регулярное выражение для проверки слов: проверять ввод слов больше не нужно.
- В `FillwordGenerator` метод `solveAndShow(size, words)` заменён на `solveAndShow(size)`, который подбирает набор слов и перебирает наборы, пока не найдёт подходящий; метод `join()` убран; вывод дополнен числом использованных наборов.
- Аргументы командной строки: теперь нужен один аргумент (размер), а не размер и слова.
- Лимит времени поиска теперь действует на каждый набор слов (2 секунды), а не на весь запуск (было 20 секунд).
- Алгоритм размещения слов (`FillwordSolver`) не менялся.
